# 决策模型构建器

把问题建模为一条可检查的推理链：决策问题 → 目标与约束 → 变量与因果 → 证据与假设 → 方案结果 → 压力测试 → 行动建议。

## 核心原则

- 先定义决策，再做分析；没有决策的问题容易变成信息堆积。
- 先应用硬约束，再比较偏好；不可行方案不参与加权评分。
- 分开记录事实、估计、假设和价值判断，不把主观权重伪装成客观事实。
- 使用能改变选择的最小模型；避免为了“专业”增加无决策价值的复杂度。
- 给区间、情景和阈值，不用小数位制造虚假精确。
- 区分决策质量与结果好坏；好决策也可能遇到坏结果。
- 保留“不行动”“延迟”“小规模试点”“分阶段投入”等真实选项。
- 明确谁负责决定、何时决定、何时复盘，否则模型不能落地。

## 工作流程

### 1. 写出决策声明

用一句话表达：`[决策者] 要在 [时间点] 前决定 [选择什么]，以实现 [目标]，同时满足 [关键约束]，评估周期为 [时间范围]。`

补齐以下字段；信息不足时先作显式假设，不要用大量问题阻塞工作：

- 决策者、截止时间、不可逆程度和复盘时间
- 现状方案、候选方案、可组合或分阶段方案
- 必须满足的约束、禁止触碰的红线、关键利益相关者
- 成功指标、失败条件、时间范围和比较基准

### 2. 建立因果骨架

从结果指标向前追问驱动因素，画出必要的因果链或问题树。为每个关键变量写明：

- 定义、单位、方向和时间范围
- 可控/不可控、领先/滞后、存量/流量属性
- 证据来源、基准值、合理区间和置信度
- 与其他变量的依赖关系，避免重复计算同一价值

不得仅用相关性宣称因果。需要诊断或因果判断时，读取 [模型目录](references/model-catalog.md) 中的“诊断与因果模型”。

### 3. 选择最小充分模型

根据问题类型选择主模型，不要默认使用加权评分表。读取 [模型目录](references/model-catalog.md) 并优先选择一个主模型；仅在不同模型回答不同子问题时组合使用。

常见映射：

- 查原因：问题树、假设树、因果图
- 多方案权衡：多属性效用/加权评分
- 风险下二选一：决策树、期望值、后悔值
- 排优先级：价值—成本—风险或 RICE/WSJF 的适配版本
- 资源分配：约束优化、边际收益
- 高不确定决策：情景分析、敏感性、信息价值、真实期权
- 验证关键假设：实验设计、贝叶斯更新或阶段闸门

### 4. 写出模型规格

在计算前固定：

1. 输出变量：模型最终解释或比较什么。
2. 输入变量：定义、单位、方向、范围和数据来源。
3. 关系式：变量如何影响结果；说明线性、阈值、上限或交互作用。
4. 约束：预算、时间、合规、能力、依赖和最低门槛。
5. 假设：支持每条关系的可证伪陈述。
6. 判定规则：何种结果触发选择、试点、延迟或停止。

对评分型模型，确保标准尽量相互独立、覆盖完整、方向一致，并给每个评分锚点写出可观察含义。不要对未经定义的 1–10 分直接加权。

### 5. 建立证据表

为关键输入记录：`变量 | 基准值/范围 | 类型（事实/估计/假设/偏好） | 来源与日期 | 置信度 | 失真风险 | 待验证动作`。

优先补充“同时具备高影响和低置信度”的信息。外部事实可能变化或决策风险较高时，检索并引用最新的一手资料；无法验证时保留未知，不要编造数字。

### 6. 计算并比较

按顺序执行：

1. 删除违反硬约束的方案。
2. 计算基准情景，并保留计算过程和单位。
3. 对关键不确定变量计算保守、基准、乐观情景。
4. 给出方案间差异，而不只给总分。
5. 找出选择发生反转的临界值。

当所有标准已经定义为“0–100 且越高越好”的区间评分时，可运行 Python 3.9 或更高版本（如 `python`、`python3` 或 `py -3`）调用脚本。根据宿主提供的 Skill 路径定位脚本，不要假定当前工作目录就是 Skill 目录：

```text
python "<skill-root>/scripts/score_options.py" --input decision.json --format markdown
```

输入格式和解释见脚本的 `--help`。不得用脚本替代评分定义、证据判断或硬约束检查。

宿主无法执行脚本时，可直接按相同定义计算并展示可复核的过程；若无法可靠完成计算，明确缺少的能力与未验证结果。

### 7. 压力测试

至少完成以下四项：

- 敏感性：哪些输入或权重最能改变排序？反转阈值是什么？
- 情景：相关变量共同恶化或改善时，结论是否稳定？
- 反证：什么证据最可能证明当前模型错误？
- 执行风险：二阶效应、激励扭曲、依赖、锁定效应和退出成本是什么？

对高代价或难逆转决策，再增加预演失败（premortem）、最小最大后悔和信息价值分析。若再收集信息的成本低于它可能避免的损失，优先验证而非立即下注。

### 8. 形成建议与行动

用“建议 + 理由 + 条件”表达结论，不把模型分数当作自动决策：

- 推荐什么，以及为何优于次优方案
- 结论依赖的三项以内关键假设
- 什么新证据或阈值会改变建议
- 立即动作、负责人、截止时间、领先指标和停止条件
- 复盘日期及届时更新哪些输入

使用 [输出模板](references/output-templates.md) 组织决策备忘录、快速比较或模型审计。

## 质量门槛

交付前确认：

- 决策问题、比较基准和“不行动”选项清楚
- 硬约束与偏好标准分开
- 变量定义、单位和时间范围一致
- 关键数字可以追溯到证据或显式假设
- 没有重复计算同一收益或把相关性当因果
- 至少展示一个基准情景和一个压力情景
- 指明结论的敏感点、反转条件和未知项
- 建议包含动作、触发器、停止条件和复盘机制
