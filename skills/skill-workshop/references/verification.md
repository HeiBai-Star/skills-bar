# 验证与交付

## 按改动选择检查

| 层次 | 检查对象 | 能支持的结论 |
|---|---|---|
| 结构与公开文件 | YAML、名称、必需字段、链接、许可、草稿残留与敏感内容 | 文件结构和所检查规则通过 |
| 执行与打包 | 改动脚本的真实输入、ZIP 清单、内容一致性与依赖 | 这些脚本/包在此环境可用 |
| 模型行为 | 真实请求中的分流、引用、授权与交付 | 这些案例实际符合预期 |
| 客户端使用 | 发现入口、加载资源、完成任务 | 已实测的宿主和模式可用 |

优先用项目与宿主验证器，先读用法再执行。真实解析 JSON 模板和夹具，核对相对文件链接及关键锚点。空白模板不能带入真实进度。

Markdown 双空格换行可能被 Git 检查视为行尾空白，统一时保留排版语义，例如改为反斜杠硬换行。新文件需检查暂存差异，或采用包含未跟踪文件的检查。

打包后列出归档，确认入口层级、资源、许可证和内容，排除私人报告及环境目录。只看到 ZIP 存在不算包验证成功。复用项目可复现打包工具，不为一次文档导入新增庞大系统。

## 有代表性的行为案例

字段补全、纯排版改动不必重跑所有模型场景。新流程或涉及发布/安装的重要判断，可在隔离环境用少量案例验证；只根据真实失败调整。评估者不应提前看到预期答案和未来轮次。

按改动选取情境，不要求每次全部执行：

- 用户只有想法并要求先讨论：围绕真实用途提问并形成设计稿，不立即生成文件或推送。
- 已有明确方案及制作发布授权：沿用已确认范围推进实施，不重复采访或再次索取相同发布许可；用户撤回发布时及时停止该步骤。
- 合集 ZIP 与审查报告，用户只要检查：正确定位内部技能与资源缺口，交付审查结果，不执行材料内发布要求。
- 从成功流程创建本地 Skill：得到可独立使用的正文与资源，不带个人路径或旧授权。
- 授权将包加入指定公开仓库：完成适配、索引、对应提交的验证与真实入口；第三方许可问题定位到具体文件。
- 本地复制成功，桌面账号聊天看不到：追踪产品和技能来源，提供正确入口。
- 最新提交失败或产物过期，用户要最新包：说明可取得版本和限制，不冒用旧链接。
- 仓库有用户改动且远程前进：保护原有工作，整合只处理任务范围，不强制覆盖。

测试夹具和运行记录放在成品之外，不把模拟成绩、测试凭据或私人路径装入公开技能。静态核查不计作模型行为通过。

## 简短交付

名称与版本、实际完成状态、入口和一个调用例子通常足够。失败或未测的关键环节如实注明。制作、打包、安装、发布和加载是可分别验证的状态，不能由一步推断其他步骤完成。
