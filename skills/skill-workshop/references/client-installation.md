# 客户端安装与同步诊断

## 先识别实际使用入口

格式可读、目录已复制、宿主已发现和任务运行成功是不同证据。用户说“Claude”“Grok”“手机”时，不只按模型名称决定安装方式；必要时确认产品、模式与版本。

| 使用入口 | 核对重点 |
|---|---|
| 本地 Agent / 编程客户端 | 实际支持的发现目录、配置优先级、刷新机制与所需工具 |
| 桌面或网页账号技能 | 当前账号的上传入口、启用状态与限制；本机文件不自动等于账号技能 |
| GitHub URL 导入器 | 是否获取完整目录；是否支持分支与子目录 |
| CC Switch 等管理器 | 源目录、启用目标、同步方式和日志；管理器成功不等于模型已使用 |

Codex、Claude Code、Gemini CLI、OpenCode、Grok Build、Hermes 等具体路径和能力应核对当前环境、项目安装器与官方文档。不能从编程客户端支持 Skills 推断同品牌普通聊天也可导入；不为“兼容”强制安装所有客户端。

## Claude 的技能来源

官方 [Claude Skills 使用说明](https://support.claude.com/en/articles/12512180-use-skills-in-claude)在 2026-10-03 核对时支持将单技能文件夹 ZIP 上传到 Customize → Skills。实际指导时重新核对当前入口。

该文档也说明符合条件的 Claude Code 能读取同一 Claude 账号启用的技能，这是从账号到 Code 的单向同步。不能据此推断本地 Code 技能目录会反向上传到桌面聊天账号。

当管理器显示已安装、桌面聊天看不到时，先判定技能来源，再提供相应导入或启用步骤。只有上传成功且账号中可见、启用后，才能报告账号安装完成。

## 完整资源与更新

需要 references/、assets/ 或 scripts/ 的 Skill 必须包含这些文件。只下载入口的导入器可能看见描述却缺规则，应改用完整目录或单技能 ZIP，不能删掉关键方法来掩盖资源缺失。

手机没有某个自定义协议处理器时，提供确认存在的 GitHub 子目录或下载入口，不假定手机能运行桌面 CLI。

按用户指定的客户端与目录安装，先检查同名版本和个人修改。优先沿用当前管理器；新装核对完整复制，更新使用明确替换策略或备份，避免两个管理器交替覆盖同一目录。必要时比较相对文件清单与摘要。

复用安装器前检查真实目标。全局设置、管理员运行或系统开发模式不应成为所有技能的默认前提。

## 软链接失败的诊断顺序

1. 看错误、对应时间的日志与同步设置；确认源入口、目标父目录、目标是否占用或为失效链接。
2. “创建符号链接失败”只说明该步骤失败。权限、系统配置和目标冲突要由证据区分，没有操作系统错误码时把原因表述为推断。
3. 若管理器支持复制且错误来自链接方式，可建议或按授权切换后重试。说明设置影响范围，不为一个技能擅自重配全部客户端。
4. 核对新日志、目标文件及宿主加载。用户随后说“仍看不到”，继续检查产品与技能来源，而非重复相同修复。

无论链接、ZIP 还是本地源，结论只覆盖实际检查的宿主和模式。
